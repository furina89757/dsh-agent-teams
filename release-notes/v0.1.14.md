# AgentTeams v0.1.14

This release ports AgentTeams onto the DeepSeek Harness **0.1.5-rc** line, where the host moved or removed several plugin seams the previous releases were built on.

## Compatibility

- Requires dsh `0.1.5-rc.1` or newer. AgentTeams `<= 0.1.13` remains the choice for the `0.1.0-rc` / `0.1.1-rc` hosts.
- Member spawn, delivery, the browser card, and settings access now use the seams the current host actually publishes (see below).

## Fixed & Improved

- **Member routes survive cold resume without the removed setup hook**: dsh 0.1.5-rc.1 deleted `ctx.subagents.registerContinuableSetup`, so `spawnMember` now passes the resolved provider/model/reasoning effort in the `startContinuable` request. Harness persists them into the durable subagent descriptor, and a cold-resumed member restores its route from there. Members created by an older AgentTeams have no persisted effort and fall back to the target model's default.
- **Retired-member guard follows the renamed delivery seam**: the guard now wraps `ctx.subagents.sendMessage` (the old `followup` name is gone), so retired members still cannot be cold-resumed by a stray message.
- **Conversation card registers through the new client seams**: `@deepseek-ai/dsh-client-runtime` was removed upstream, so the browser bundle now imports its types from `@deepseek-ai/dsh-api-session-controller/client`, `@deepseek-ai/dsh-client-store`, `@deepseek-ai/dsh-client-ui-chat/client`, `@deepseek-ai/dsh-client-ui-renderer/client`, and `@deepseek-ai/dsh-client-ui-session/client`; the card registers with `ctx.uiConversation.events.register(...)` and merges `ChatNodeDataMap` in `@deepseek-ai/dsh-client-ui-chat/client`.
- **Team archiving tolerates longer Windows locks**: archiving a team directory now retries a transient delete-sharing lock with a directory-sized budget instead of the file-sized one, so archiving no longer loses to a ~140 ms holder.

## Verification

- `pnpm build` produces the host half and the browser bundle; the host and client halves typecheck against the published `0.1.5-rc.2` packages.
- The offline suite passes: `scripts/verify.mjs` (140 checks, including the real Windows lock integration on Windows), `scripts/lifecycle-verify.mjs`, `scripts/stress-verify.mjs` (eight-member fault-injection stress), and the skill-mirror check.

## Known Limitation

- A member created before this release resumes with its provider/model and the target model's default reasoning effort, because the historical subagent descriptor has no effort field to restore.

## Installation

```sh
dsh plugin --profile web add @nanmicoder/dsh-agent-teams
```

# AgentTeams v0.1.14

本版把 AgentTeams 移植到 DeepSeek Harness **0.1.5-rc** 线；这条线上宿主移动/删除了若干插件接缝，旧版本因此无法启动。

## 兼容性

- 需要 dsh `0.1.5-rc.1` 或更高版本；仍在使用 `0.1.0-rc` / `0.1.1-rc` 的宿主请继续使用 AgentTeams `<= 0.1.13`。
- 成员创建、消息投递、浏览器卡片与设置访问全部改用当前宿主真实提供的接缝。

## 修复与改进

- **冷恢复不再依赖被删除的 setup 钩子**：dsh 0.1.5-rc.1 删除了 `ctx.subagents.registerContinuableSetup`，现在 `spawnMember` 直接把解析好的 provider/model/思考强度放进 `startContinuable` 请求；宿主会把它们写入 durable 的 subagent descriptor，冷恢复时按 descriptor 还原路由。旧版本创建的成员没有持久化思考强度，会退回目标模型的默认档。
- **退役成员守卫跟随改名后的投递接缝**：守卫改为包裹 `ctx.subagents.sendMessage`（旧的 `followup` 已不存在），退役成员依然无法被误发消息冷恢复。
- **会话卡片改用新的客户端接缝**：上游移除了 `@deepseek-ai/dsh-client-runtime`，浏览器 bundle 的类型来源改为 `@deepseek-ai/dsh-api-session-controller/client`、`@deepseek-ai/dsh-client-store`、`@deepseek-ai/dsh-client-ui-chat/client`、`@deepseek-ai/dsh-client-ui-renderer/client`、`@deepseek-ai/dsh-client-ui-session/client`；卡片通过 `ctx.uiConversation.events.register(...)` 注册，`ChatNodeDataMap` 合并目标改为 `@deepseek-ai/dsh-client-ui-chat/client`。
- **归档更能容忍 Windows 目录锁**：归档团队目录改用「目录级」重试预算，不再输给约 140ms 的临时占用。

## 验证

- `pnpm build` 产出宿主侧与浏览器 bundle；宿主侧与客户端均按已发布的 `0.1.5-rc.2` 包通过类型检查。
- 离线验证全绿：`scripts/verify.mjs`（140 项，含 Windows 真实锁集成）、`scripts/lifecycle-verify.mjs`、`scripts/stress-verify.mjs`（八成员故障注入压力）与 skill 镜像检查。

## 已知限制

- 本版之前创建的成员，冷恢复时会还原 provider/model，但思考强度退回目标模型默认档——历史 subagent descriptor 里没有该字段。

## 安装

```sh
dsh plugin --profile web add @nanmicoder/dsh-agent-teams
```
